# PromptHub / 画引采集要素标准

**状态：生效**  
**用途：所有手动收藏、插件识别、Grok 候选导入、公开网站采集、微信公众号文章识别和后续质检，均按本标准判断是否入库。**

## 1. 核心原则

PromptHub / 画引不是网页内容搬运库。系统不得把页面、帖子或文章中的所有文本都提取入库，只收集能沉淀为独立提示词详情页的有效素材。

一条内容只有同时满足以下条件，才允许进入主站：

- 有可复制使用的完整提示词正文。
- 有对应的结果图、视频或稳定封面媒体。
- 有可追溯的来源 URL。
- 能生成明确标题、分类、标签和模型信息。
- 通过唯一性验证，不与已有来源或提示词重复。

一句话标准：**能生成独立详情页，用户可以复制后直接使用，有图或视频验证效果，来源清楚，分类明确，才收集。**

## 2. 必须提取的要素

### 2.1 来源信息

每条收藏必须保存：

- 原始页面 URL。
- 具体帖子、文章、案例或详情页 URL。
- 作者、博主、网站名或来源名称。
- 发布时间；没有发布时间时保存采集时间。
- 来源类型，例如 `x`、`github`、`wechat`、`public_site`、`manual_import`。

X 来源必须是具体 `/status/<id>` URL；不能使用首页、搜索页、书签页或列表页作为来源。

### 2.2 提示词正文

只保存真正可复制使用的提示词正文。提取时必须：

- 保留主体、场景、风格、构图、光线、镜头、材质、色彩、动作、参数、负面提示等有效生成信息。
- 优先识别结构化 Prompt 区块、代码块、引用块、编号方案和明确的提示词字段。
- 对长线程或长文章，提取完整提示词，不截断成标题或摘要。
- 去掉平台、模型或社交前缀，例如：
  - `GPT Image 2 on ChatGPT 提示`
  - `GPT IMAGE 2 ON CHATGPT Prompt`
  - `Nano Banana Prompt`
  - `No grok pls`
  - `Prompt:`
  - `提示词：`
- 去掉寒暄、推广话术、教程废话、作者备注、关注引导和无关链接。

不得把模型名称、页面标题、SEO 摘要、教程段落或广告文案误当成完整提示词。

### 2.3 标题

标题用于列表页和详情页展示，必须：

- 控制在 20 个汉字以内。
- 根据完整提示词或结果媒体提炼重点。
- 包含明确主体、场景、用途或风格中的至少两个有效信息。
- 避免泛化标题，例如 `图片提示词`、`今日提示词`、`高质量提示词`、`产品图`。

推荐标题形态：

- `复古 CCD 少女人像`
- `金黄芒果饮料广告`
- `玻璃盒战斗场景`
- `极简电商产品主图`
- `赛博城市电影海报`

人工编辑并锁定的标题不得被自动任务覆盖。

### 2.4 结果图或视频

每条收藏必须至少有一个有效视觉结果：

- 图片或视频地址必须是 HTTPS，且能稳定访问。
- 图片优先提取主图，也可以保存多图。
- 视频允许收藏，但必须有封面、视频媒体或可追溯原帖。
- 记录媒体类型：`image` 或 `video`。
- 能识别时记录宽高比，例如 `1:1`、`3:4`、`9:16`、`16:9`。

只有提示词但没有任何结果图、视频或封面验证的内容，不直接入库。

### 2.5 分类

分类以内容用途优先，其次再看视觉风格和主题。

一级分类建议包括：

- `人像`
- `电商视觉`
- `视频提示词`
- `建筑空间`
- `品牌海报`
- `产品摄影`
- `插画艺术`
- `UI 与界面`
- `场景叙事`
- `其他应用`

电商视觉是重要一级分类，下面必须继续识别二级用途：

- `产品主图`
- `场景种草`
- `广告海报`
- `商品详情页`
- `模特展示`
- `UGC / 口碑`
- `包装视觉`
- `品牌 KV`
- `促销活动图`
- `电商视频`

视频内容同时保留 `mediaType: video`，电商视频仍属于 `电商视觉`，并能通过视频筛选找到。

### 2.6 标签

标签用于筛选和 SEO，不得堆砌无关词。可从以下维度提取：

- 风格：写实、电影感、复古、极简、赛博、国风、日系、韩系、3D、插画。
- 场景：室内、街头、海边、工作室、货架、展厅、城市、自然。
- 用途：电商、广告、社媒、头像、海报、短视频、产品图、详情页。
- 内容：人物、服装、饮料、家居、美妆、汽车、食品、建筑、科技。

标签数量应适中，优先保留能真实帮助搜索、筛选和分类的词。

### 2.7 模型信息

模型信息必须来自来源文本或页面明确标注。没有明确模型时，使用：

- `通用 AI 图像模型`
- `通用 AI 视频模型`

不得凭图片风格猜测具体模型。

### 2.8 同步状态

每条入库记录或候选队列项需要能追踪：

- 本地队列状态。
- 是否已提交 GitHub 主站队列。
- 是否已写入 GitHub 主站。
- `githubSyncedAt`。
- 国内站发布时间或待发布状态。
- 失败原因。
- 重试次数。

不能把“本地队列中”“已提交入站文件”或“等待主站合并”称为“已同步”。

## 3. 唯一性验证

写入 GitHub 主站前必须先去重：

1. 来源 URL 去重：规范化后的具体来源 URL 已存在时，跳过新增。
2. 提示词指纹去重：去掉空白、大小写差异、平台前缀后，完整提示词相同则跳过新增。
3. 媒体 URL 去重：同一主图或视频已存在时，进入相似检查，不直接重复入库。

重复内容可以补全已有记录缺失字段，例如宽高比、标题、标签或模型信息；不得新增另一条重复记录。

## 4. 完整性检查

以下字段缺失时，不得直接写入主站：

- 标题。
- 完整提示词。
- 结果图、视频或稳定封面。
- 分类。
- 来源 URL。
- 采集时间。

以下情况进入待修复或直接拒绝：

- 提示词太短，无法独立生成画面。
- 提示词明显只有摘要、标题或片段。
- 图片失效，且没有可替代媒体。
- 来源无法追溯到具体帖子、文章或案例。
- 分类无法判断，且内容质量不足以人工补全。

## 5. 不应该收集的内容

以下内容不得写入主站：

- 只有教程，没有完整提示词。
- 只有图片，没有可复用提示词。
- 只有链接、推广文案或工具宣传。
- 纯平台广告、课程广告、付费墙预览。
- 明显重复转发或二次搬运，且没有原始来源。
- 版权不清晰、明确禁止转载、或需要登录/付费才能查看完整内容。
- 低质量、过短、无法生成具体画面的描述。
- 标题党内容，但正文没有有效 Prompt。
- 社交平台前缀、寒暄、作者备注、关注引导和无关评论。

## 6. 不同来源的特别规则

### X / Twitter

- 只接受具体状态页 URL。
- 不自动扫描登录态首页、书签页或时间线。
- 通过 Grok CLI 或用户手动提供候选时，仍必须执行完整提示词、媒体、来源和去重校验。
- 线程内容需要合并真实提示词正文，但不能合并无关回复。

### GitHub

- 只采集公开仓库中明确授权、可复用的案例。
- 优先使用仓库 README、docs、gallery 等可追溯页面。
- 保留许可证或来源说明。
- 不采集需要私有权限、隐藏接口或不明确授权的内容。

### 微信公众号

- 只识别公开文章中明确展示的提示词案例。
- 不把正文教程、营销介绍或平台口号当成提示词。
- 多个案例必须拆成多条独立候选，每条都要有对应媒体和来源。

### 公开网站

- 必须先确认页面公开可访问，并有清晰的内容来源。
- 不绕过登录、会员、付费墙、robots 限制或隐藏接口。
- SEO 摘要不能代替完整提示词。

## 7. 入库前决策清单

每条候选入库前，按顺序回答：

1. 这是不是完整、可复制、可直接生成画面的提示词？
2. 有没有对应结果图、视频或封面？
3. 来源是不是具体、可追溯、公开可访问？
4. 是否已经按来源 URL 或提示词指纹存在？
5. 标题是否能在 20 个汉字以内准确概括内容？
6. 分类和标签是否能帮助用户搜索与筛选？
7. 自动推断字段是否允许后续编辑修正？
8. 状态文案是否准确说明当前阶段，而不是误称已同步？

只要其中任一关键项失败，就不得直接写入 GitHub 主站。
